# web_fetch is Approval-gated and reuses Standing Approval on the URL's DOMAIN

web_fetch is the first tool that reaches outside the Project Root: doc lookups need the network, and the absolute-path confinement story every other filesystem tool lives under (`resolve_absolute_in`, root/memory containment, ADR-0060) does not apply to a URL. The permission model is therefore the design, not a detail.

Every fetch passes the Approval gate. The gate is the same one run_shell_command uses, and Standing Approval (ADR-0005) applies - but web_fetch scopes it to the URL's DOMAIN, not the exact URL. Approve-always records the hostname (`docs.rs`), and a later fetch to any path under that host auto-approves. This is faithful to qwen's `WebFetch(<hostname>)` permission rule (web-fetch.ts `getConfirmationDetails`): the hostname is parsed from the URL, and on an unparseable URL the raw string stands in for the domain (qwen's `catch { domain = url }`). The gate text `gate_text` returns for web_fetch is that hostname; run_shell_command still returns the full command, so the two facts ("does this gate", "what text") stay derived from one lookup.

Dated reversal (2026-07-30, P2b): this ADR originally chose EXACT-URL matching (approve `https://docs.rs/tokio`, nothing else) and rejected domain allowlists as a widening seam. P2b reverses that: qwen is domain-scoped, and the port is faithful to qwen (the governing frame - suspenders IS a qwen-code Rust port). The tradeoff is real and named below.

Chosen: domain-scoped Standing Approval (approve `docs.rs` once, fetch any path under it). Faithful to qwen, and the ergonomics fit how the tool is used: a doc-reading Run fetches many paths under one host (docs.rs/tokio, docs.rs/serde, ...), and re-prompting per URL would drown the user in near-identical modals. The user still reviews the host before the first fetch, which is the review that matters for the exfiltration channel: a GET's URL is a write channel (anything the model read can leave in a query string), and the host is where that data would go.

Considered and rejected:

- **Free read access** ("it's only a GET"). A GET's URL is a write channel: anything the model has read can be exfiltrated in a query string to a server the model chose. Showing the host in the modal and gating on it is the review that closes it.
- **Exact-URL matching** (the ADR's original choice: approve `https://docs.rs/tokio`, nothing else). Tightest possible, and it is the no-widening rule ADR-0005 holds for command prefixes - but it is NOT what qwen does, and fidelity to qwen governs (the port frame). It also re-prompts on every trivially different path, which is the cost domain-scoping removes. This is a deliberate divergence from ADR-0005's no-widening stance, scoped to web_fetch only: the widening is one host, reviewed once, and the host - not the path - is the security boundary that matters for a read-then-exfiltrate channel.

## The `format` param, content-type handling, and the fixed timeout

web_fetch takes an optional `format` param (`text` default, or `markdown`) that negotiates the request's `Accept` header: `text` asks for `text/plain`, `markdown` asks for `text/markdown` (faithful to qwen's Accept-negotiation). The response body is decoded by what the tool asked for, NOT gated on the server's declared `Content-Type`: web_fetch NEVER errors on an unexpected content-type. A body served as `application/octet-stream` or an odd MIME is still read as text and handed on, because a doc server mislabeling a page must not sink the fetch. HTML converts to readable text before processing; other bodies are read as text per the negotiated format.

The request timeout is a FIXED 10 seconds - not configurable, not the run_shell_command timeout. A slow doc server returns a timeout error rather than parking the Run.

Consequences: users approve each distinct HOST once per Session (not each URL). The fetched content is capped at 100 000 chars and handed to a bounded model side-query (ADR-0055) with the user's `prompt`, so the tool returns a prompt-guided extraction rather than the raw page (faithful to qwen web-fetch.ts). The download is guarded at 2 MB so a huge body never streams into memory before the content cap trims it. GitHub `blob` URLs are rewritten to their `raw.githubusercontent.com` form before the fetch (qwen parity). A fetch or extraction failure returns qwen's `Error during fetch for {url}: {message}`.
