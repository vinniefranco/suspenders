# Screen, Transcript, Composer: the UI core split

The pure UI core (ADR-0001) had grown into one struct doing four jobs - display history, Composer state, modal state, status-bar state - with every feature adding arms to two fat folds (`handle_key` at ~300 lines, `apply_event` at ~20 arms) and the `messages` Vec mutated from six-plus sites under comment-enforced invariants. The struct was also named `Transcript`, which CONTEXT.md defines as the display-side history alone, so the code and the glossary disagreed about what a Transcript is.

The core splits into three modules, aligned with the glossary:

- **Screen** (the renamed fold root): owns the Approval modal, the Agent status, the display toggles, and the status-bar figures. Its folds route: the Approval gate first, then the Composer's first refusal, then the Screen's own arms (scroll, toggles, Escape-as-Cancellation).
- **Composer**: owns the draft and cursor, the Slash Command menu cursor, the selector overlay, and the prompt-history ring. A first-refusal fold - `handle_key(key, status)` returns `Consumed { effects, notice }` or hands the key back as `Refused(Key)`, and `apply_event` does the same for the overlay-filling events - so contextual ownership (the wheel navigates an open menu but scrolls the viewport otherwise) lives in one place. Both overlays are Composer states; the Approval modal is the only modal. The submit-vs-steer retry stays in the Screen: it touches only Agent status, and the draft must survive the retry.
- **Transcript** (the deepened store, now matching its glossary entry): owns the settled items, the revision counter, the Streaming snapshot (module goes private), and Presentment (the Presenter list moves in). Named event-shaped verbs (`tool_call`, `tool_result`, `steering_queued`/`steering_delivered`, `close`, `push`/`user`/`info`); the two structural edits share one private supersede funnel. Invariants move from comments into the seam: appends never bump the revision, removals always do (the RenderCache contract), Tool Result pairing is by id never position, and Presentment runs before every append - a deliberate WIDENING, not a relocation: `present` previously ran only on Tool Call/Result items, and now every appended item (Info and Voice lines, User promotions, settled streaming text) passes through it, with an empty Artifacts map on the non-tool appends. Presentment failure lines bypass Presentment (the recursion bound). Voice strings stay with the Screen except the two the store's own invariants require verbatim: the pending-steering marker and the Presenter-failure line.

Considered and rejected: migrating to a Flux architecture (dispatcher, stores, subscriptions). The core already has Flux's unidirectional flow - events in, pure fold, effects out - so a dispatcher would fail the deletion test (`tokio::select!` in the adapter already is one), while costing the pure-fold test surface and moving the submit-steer race handling into async code. What Flux's per-feature stores actually buy is had inside TEA as the sub-modules above. Also rejected: a Modal sum type over the Approval modal and the selector overlay - the selector is draft-coupled Composer state, and forcing it under a Modal enum would leak the draft's filter and backspace rules across two modules.

ADR-0001's seam is unchanged: the core stays pure and UI-free, the adapter still executes effects and draws; its "pure Transcript core" now reads "pure Screen core", and its entry-point list matches the split folds (`input_changed` is gone - the Composer owns editing).
